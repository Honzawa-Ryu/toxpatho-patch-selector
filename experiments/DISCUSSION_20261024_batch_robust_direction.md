# プロジェクトの目的と、バッチ効果に頑健な方向 — 2026-10-24

ユーザーの方針（2026-10-24）。プロジェクト全体に関わるので、個々の実験ではなくここに記録する。

## 目的

**毒性病理画像のpatchを、データドリブンにコアに分ける。** 正常な肝組織、胆管などの構造、所見を、きれいに分けられることを目指す。

- これまでのアプローチ（0017のコンセンサスによるコア、0018の2段階）は悪くないと考えている。
- ネックはデータのバッチ効果が大きいこと。試験・slide・スキャナの差（ストライプに沿った帯を含む）が埋め込みの主な変動になり、コアが「異常の量 × 化合物（試験）」の格子に近くなって、きれいに分かれない（0018 README）。

## 方向: slide内の関係性を使う

- slideのすべてのpatchを埋め込むと、slideごとに差が出るのは仕方ない。
- 一方、**slideの中でのpatch同士の「関係性」は、バッチ効果があっても保たれているはず**。ここに切り込みたい。
- slideごとに平均を引いた（0017 `block6_clean_centered`）のは、この考えの最初の一歩。コアは化合物をまたぐようになったが、Controlとの分離は弱まり、slide内のストライプの差が目立った。
- 今後、ここからいくつか模索する（具体策は個々の実験で決める）。

## 候補（未決、思いつきを含む）

- slide内の標準化を強める: 平均に加えて分散・共分散をそろえる、slide×ストライプ単位で平均を引く
- 埋め込みの事後調整でslide間差の方向をつぶす（Controlの複数slideで一致する方向だけを残す）: #12
- UNIに事後でドメイン敵対学習（DANNなど）をかけ、slide・試験・scannerを当てられない表現にする: #13
- 関係性そのものを特徴にする: slide内でのpatchの順位・近傍関係・距離の構造を使う（slide内の相対位置で比べる）
- patchの空間的な位置情報（周囲のpatchとの関係）を組み込む: #9

- 【Todo、2026-11-01ユーザー】GraphTox に関連するアプローチを試す。特に**画像の階層性（5×・10×・20×）と隣接性（patch 間のグラフ）の取り入れ**はいずれやりたい。
  論文: Li L, Shelton L, Forest T, et al. "Unsupervised Anomaly Detection on Preclinical Liver H&E Whole Slide Images using Graph based Feature Distillation." MICCAI 2025（2025-09-19 公開、査読済み）。DOI: 10.1007/978-3-032-05162-2_64
  要点: ラット肝 WSI で、正常組織だけで学んだ Feature Distillation の誤差から異常領域を検出する。5×・10×・20× を組み合わせ、patch 間の空間関係をグラフにする。270 万 patch で事前学習した倍率対応の基盤モデルを使う。独立テストで、非グラフ型の最良手法より AUC +11.1%、UNIv2 を使うグラフ型より +8.1%。コードは著者へのメール請求（公開リポジトリは未確認）。
  こちらでの意味: 毒性病理では周囲の組織構造が判断材料になる（肝細胞肥大は細胞の形態だけでなく、小葉内の分布や周囲との関係）。patch の異常度に空間構造と倍率の情報を組み込む参考。
  試したい実験: 同じ Ctrl/投与群の分割で、patch 単体の kNN 異常検知、単一倍率の Feature Distillation、マルチ倍率の Graph Distillation を比べ、異常 patch の Recall@K と slide 単位の AUROC で評価する。
  限界: 比較ベースラインが限られ、他の病理 FM や MIL 手法に対する優位は未確立。
  関連: 隣接性は 0025 の「境界を保つ伝播」（patch のグリッド近傍、2 hop）で一部試した。位置情報の組込みは #9。倍率の階層性は未着手（特徴は 20× のみ）。: #15

  要点: 目的関数は k-means と同じ。各クラスタの和と個数をミニバッチごとに指数移動平均で更新する。Lloyd の 25 epoch の誤差に 1.2〜3 epoch で届き、人工データで局所解に捕まる割合が 15〜46% → 0〜4%。
  比較: 0032 と同じデータ・表現・k = 100 で Lloyd の合議と並べ、seed 間の ARI、名前付きプロトタイプの純度・coverage を見る。
